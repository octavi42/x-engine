## 5. Thread · multi-model LLM app failure modes (roadtosf)

### Hook (post 1)

> shipping roadtosf meant orchestrating Sonnet 4.6 + Haiku 4.5 + ElevenLabs + OpenAI image gen. 4 model calls per scene, 4 ways to fail
> 
> 5 lessons I'd take into the next multi-model app:

### Post 2 (cost split)

> cost split: Sonnet 4.6 only for arc gen, 1x per episode. Haiku 4.5 runs every per-scene call. using Sonnet on every scene would 5x the bill for 0 quality lift on per-scene work

### Post 3 (cap real cameos)

> cap real-figure cameos at 1 per episode. more than that breaks the 'rare cameo' feeling. NPC names that collide with real actors get auto-renamed before they ship (Dev Patel → Devraj Mehta)

### Post 4 (tolerate malformed shapes)

> tolerate malformed cast shapes. Sonnet sometimes returns broken objects when forced to pivot mid-arc. zod validate, fall back to last-known-good cast, never crash the run

### Post 5 (pre-fire next episode)

> pre-fire the NEXT episode while the player walks the current final scene. by the time they tap continue, the next arc + scene 0 image are warm. latency-hiding via level design, not faster inference

### Post 6 (ElevenLabs scope)

> ElevenLabs Scribe Realtime needs the `speech_to_text` scope on the API key. otherwise token mint returns 401 missing_permissions, symptom shows in browser 5 min after the cause. enable the scope on key creation

**Source:** sources/raw-ideas/items/roadtosf.md · multiple sections (cast persistence, latency hiding, ElevenLabs Scribe scope, two-model split)
