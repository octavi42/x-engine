## 3. Technical tip — Clio RNMapbox ground-plane homography

> Clio map perf tip: RNMapbox's getPointInView returns [-1, -1] for off-screen points. almost no pins became edge dots
>
> fix: 4 getCoordinateFromView calls give the camera's ground-to-screen homography. project every pin in JS. 4 native calls per update, not ~90

**Format:** bug-fix (cause → symptom → fix with a named technical detail, single-tweet)
**Type:** technical tip — Clio commit `c5c63e52daab4f447496e4c9324f6570eb17fe16` fixes an RNMapbox perf + correctness bug in the photo-pin edge-dot system. Cause: `getPointInView` answers `[-1, -1]` for off-screen points, so almost no off-screen pins ever became edge dots (the pins that should ride the screen edge as small dots when just off the camera). Fix: four `getCoordinateFromView` calls give the camera's ground-to-screen homography (a 2D projection matrix for the ground plane). Every pin, on-screen or off, is then projected in JS. Net: 4 native round-trips per update instead of ~90. Bonus: edge dots now also keep clear of stickers half past the edge. General pattern: when a native bridge returns a sentinel for off-screen points, compute the projection yourself from the camera's own calibration points.
