## 5. Thread hook with outline
**Topic:** AI coding speed vs security paradox — McKinsey finds 46% productivity gain, but security researchers find ~50% of AI-generated code has vulnerabilities.

### Hook (post 1)
mckinsey says AI coding tools cut routine coding time by 46%. security researchers say roughly half of AI-generated code contains vulnerabilities. we're shipping faster and buggier at the same time. here's what that means for builders:

### Post 2 — the speed numbers
AI coding market hit $12.8B in 2026. 92% of US devs use AI tools daily. 51% of all github commits are AI-generated or AI-assisted. the speed gains are real and measurable. but speed without security review is just faster technical debt.

### Post 3 — why LLMs write insecure code
LLMs default to insecure patterns because they trained on all public code — including the bad code. hardcoded secrets, missing input validation, injection vulnerabilities. the model reproduces what it saw most, and most code on github isn't security-audited.

### Post 4 — the fix
the fix emerging: AI-generated code + AI security scanning in the same pipeline. the solution to AI-written bugs is adversarial AI that checks the first AI's output. checkmarx, snyk, and semgrep are all shipping AI-aware static analysis.

### Post 5 — the real risk
the real risk isn't the AI. it's junior devs accepting AI output without reading it. the speed gain only works if someone still reviews the code. the most valuable engineering skill in 2026 isn't writing code — it's reading AI-generated code critically.
