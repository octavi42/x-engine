## 5. Thread — Clio's 4-layer architecture (agent is the center, backend provides ingredients)

### Hook (post 1)

> Clio's backend never writes a story. the agent does
>
> Mobile → ElevenLabs Agent → Backend → External APIs. the agent is the center. everything else is ingredient prep
>
> thread on why this shape beats the naive TTS-reads-a-script pipeline

### Post 2

> the naive shape: backend generates a script, TTS reads it out
>
> dies the moment the user interrupts, asks a follow-up, or wants a different angle. the script has no state, the TTS has no memory, and the backend has no idea what got said

### Post 3

> the flip: agent = LLM + tools + voice. backend = research service
>
> Firecrawl results come back as structured segments (facts, stories, confidence). the agent picks what to say and how. no pre-written script survives contact with the walker

### Post 4

> 20-second server-tool timeout is the constraint that shaped the backend
>
> Nominatim reverse geocode + Firecrawl queries + place-type classification all fire in parallel. no sequential chain fits inside 20s

### Post 5

> state lives in one Map keyed by ElevenLabs conversation ID. no DB, no persistence
>
> every mutation goes through the session helpers. one source of truth for location, mode, research segments, timestamps

### Post 6

> the payoff: when the user interrupts or asks a follow-up, the ingredients are already loaded
>
> no re-fetch, no re-script, no round trip. the agent picks a different angle from segments it already has
